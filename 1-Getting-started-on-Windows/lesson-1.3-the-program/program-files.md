### Preprocessing
The preprocessor handles directives that begin with a hash character `#` (e.g., `#include`, `#define`, `#ifdef`). It copies the contents of included headers, expands macros, and strips out comments, producing a pure C++ source file ready for translation.

### Compilation
The compiler takes the preprocessed text file and translates the high-level C++ code into low-level assembly language specific to the target architecture. This stage performs syntax validation, type checking, and initial code optimization.

*Note: In modern compilers, the "Assembly" stage is bundled here, automatically converting assembly code into machine-readable object code.*

### Static Linking
The linker combines all compiled object files and static library files (`.lib`/`.a`) into a single, independent executable file. All reference definitions are resolved at compile/build time, meaning the binary size is larger but contains all required code to run on its own.

### Dynamic Linking
Instead of embedding external library code directly into the executable, dynamic linking records the names of external functions and libraries inside the executable. The actual linking occurs at runtime, when the operating system loads the shared libraries (`.dll`/`.so`) into memory alongside the program, reducing overall disk and memory footprint.

---

## 2. Associated File Types Reference

### `.cpp` / `.cc` / `.cxx` (Source File)
Contains the primary implementation of functions and logic written in human-readable C++ code. These are the main entry files compiled into individual translation units.

### `.h` / `.hpp` (Header File)
Stores function declarations, class definitions, structures, and macro definitions shared across multiple source files. They allow different compilation units to understand external interfaces before linking.

### `.i` (Preprocessed File)
The temporary text output generated by the preprocessor after expanding macros and including all headers. It is rarely saved to disk unless explicitly requested for debugging macro expansions or include paths.

### `.s` / `.asm` (Assembly File)
A human-readable text file containing architectural-specific assembly language instructions generated by the compiler. Developers inspect these files to analyze low-level compiler optimizations and CPU instruction execution.

### `.o` / `.obj` (Object File)
Binary files containing compiled machine code instructions, relocated addresses, and symbol tables generated from a single translation unit. They cannot be executed directly because external references are still unresolved.

### `.a` / `.lib` (Static Library)
An archive containing a collection of multiple object files packed together into a single file for reuse. During static linking, the required machine code is copied directly into the final executable.

### `.so` / `.dll` (Shared / Dynamic Link Library)
Compiled binary libraries loaded into memory and linked to the executable at runtime rather than build time. This allows multiple running programs to share a single copy of the library in system memory, saving resources.

### `.exe` / `No Extension` (Executable File)
The final fully-linked binary file that can be natively executed by the operating system (`.exe` on Windows, or extensionless binaries with execution permissions on Linux/macOS). It contains the complete program entry point and memory map layout.
